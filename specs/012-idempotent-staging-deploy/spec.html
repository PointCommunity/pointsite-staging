Idempotent Staging Deployment

Problem

Wrangler can upload and activate a Worker, then exit unsuccessfully when a later Cloudflare API lookup fails. A blind job rerun creates a redundant version and leaves Builder reporting a false deployment failure.

Contract

  • Protected Staging is served only from staging.pointatx.org; workers.dev is disabled.
  • Every deployment is tagged with the immutable GitHub commit and labeled with the candidate checksum.
  • A normal zero exit remains success.
  • Only transient network, rate-limit, or Cloudflare 5xx exits may enter reconciliation.
  • Reconciliation succeeds only when the expected tagged version is the latest deployment and receives 100% traffic.
  • Confirmed failures remain failures. The existing live verifier remains the final authority.

Plan

  1. Add failing tests for transient classification, exact tagged-version matching, and confirmed failure.
  2. Implement a testable deployment coordinator with bounded read-only reconciliation retries.
  3. Replace the raw workflow command and disable workers.dev.
  4. Run unit, static, browser, and exact-head GitHub verification.
  5. Publish and accept a controlled Builder revision, then finish Builder Issue #25.

Boundaries

  • Do not weaken exact-candidate checks, Staging authentication, or security headers.
  • Do not write to public Production.
  • Do not retry an upload when Cloudflare already activated the expected version.
  • Preserve the user-owned dirty Staging checkout; work only in the isolated Issue #12 worktree.
